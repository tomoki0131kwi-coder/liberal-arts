# 図版（画像）の付け方

各回には、本文の第2段落のあとに、話に出てくるものや関連する画像を1枚表示する。
画像は Wikimedia Commons の自由ライセンスのものだけを使い、`img/<回id>.webp` に置く。
説明・作者・ライセンス・出典は `src/images.json` に記録され、画像の下に表示される。

## 使ってよい画像

- 使ってよいライセンス：パブリックドメイン、CC0、CC BY、CC BY-SA（GFDL など同等のものを含む）。判定は `common.ok_license`。
- 使わないもの：
  - 非営利限定（NC）、改変禁止（ND）、フェアユースの画像
  - 著作権のあるキャラクター、アニメや漫画の絵、映画の場面写真、ロゴ
  - 裸体や遺体が写るもの
  - 一般の人の顔がはっきり写る写真
- 合う画像が見つからない回は、無理に付けない。代わりに `src/images-none.json` に理由を書く。
- 同じ画像を二つの回で使わない。
- 説明文（caption）には、Commons の題名・説明文で確かめられることだけを書く。年代・所蔵先などを推測で足さない。

## 手順（新しい回を追加したとき）

1. **検索語を作る。** 回ごとに英語の検索語を2〜3個用意する。具体的なもの（人物名、作品名、場所）から一般的なものの順に並べ、`{"回id": ["…", "…"]}` の JSON にする。
2. **検索する。** `python3 tools/images/search.py 検索語.json 候補.json` を実行する。自由ライセンスの候補だけが残る。
3. **選ぶ。**
   - 候補の題名・説明文と本文を照らし、回ごとに1枚（予備を1枚まで）選ぶ。
   - 選んだものを `tools/images/picks/` に新しいファイル（例：`010-<分野>-追加.json`）として書く。
   - 書式は `[{"id", "files": [{"title": "File:…", "caption": "…"}], "alt": "…"}]`。
   - Commons の正確なファイル名が分かっていれば、検索を経ずに直接書いてもよい。
4. **取得する。** `python3 tools/images/fetch.py` を実行する。まだ取り込んでいない回だけを取得し、`img/` と `src/images.json` を更新する。
5. **目で確かめる。**
   - `python3 tools/images/sheet.py 確認.jpg <回id…>` で一覧画像を作り、内容が本文と合っているかを見る。
   - あわせて、上の「使わないもの」が写っていないか、ほかの回と重複していないかを見る。
6. **差し替え・取り外し。** 問題があれば、`picks/` にもっと新しいファイル名で書き直して、もう一度 `fetch.py` を実行する。後のファイルが優先される。`files: []` と書けば、その回の画像は外れる。
7. **ビルドする。**
   - `node build.js` を実行する。
   - 画像がなく、`src/images-none.json` に理由もない回があると警告が出る。警告がなくなるまで手順1〜6を行う。
8. **公開する。** Artifact の `files` に、新しく増えた・変わった `img/*.webp` を渡す（1回の公開で255ファイルまで）。

## Wikimedia の取得制限について

- この環境の接続元からは、キャッシュにない縮小画像の生成を求めると、すぐ 429（取得制限）になる。
- `fetch.py` は、キャッシュに残っていることの多い 1280px・330px の縮小画像と原寸を順に試し、すべて 429 なら retry-after だけ待つ。
- 制限を回避する工夫（User-Agent の偽装など）はしない。
- 原典：Wikimedia Robot policy（https://wikitech.wikimedia.org/wiki/Robot_policy）の「Media API rules」。同時接続は2以下、標準サイズの縮小画像か原寸ファイルのみを取得、と定めている。
